# 单代号时标网络进度计划图生成系统 —— 技术方案设计文档

> 版本 v1.0 · 2026-09-08
> 需求：根据**招标文件**与**工程量清单**，自动生成**时标网络进度计划图**（图片）。
> 交付物：本设计文档 + 可运行原型（`prototype/`，Node.js，已跑通样例）。

---

## 1. 概述

### 1.1 背景

在工程招投标与施工组织设计中，网络进度计划图是表达进度安排、识别关键线路的核心成果。传统做法依赖造价/计划人员手工编制：从工程量清单估算各分项工期 → 排定逻辑关系 → 绘制双代号/单代号网络图 → 反复调整。整个过程耗时且易错。

本系统目标是把这条链路**自动化 + 半自动辅助**：输入招标文件与工程量清单，输出一张可直接用于汇报/打印的**时标网络进度计划图**，并给出关键线路、总时差、自由时差等量化结果，供人工校核调整。

### 1.2 范围与边界

| 项目 | 本方案范围 |
|------|-----------|
| 输入 | 招标文件（PDF，提取工期/里程碑）、工程量清单（PDF/Excel/JSON，提取分项工作与工程量） |
| 工期 | **半自动**：规则给出建议工期，人工可改；不依赖现成定额库，用工效基准表兜底 |
| 网络图 | **单代号（AON）时标网络计划图**（需求明确单代号可接受） |
| 输出 | 图片（PNG 位图 + SVG 矢量图）+ 机读计算结果（JSON） |
| 暂不含 | 资源/费用均衡、进度优化、多方案比选、双代号（AOA）出图（列为扩展项） |

### 1.3 核心挑战

1. **PDF 表格解析**：招标文件、工程量清单版式差异大，清单表格列结构不统一。
2. **工期估算**：无定额库时，如何从「工程量」得到合理工期。
3. **逻辑关系推导**：工序先后依赖是最难自动化的部分，需「工艺模板 + 规则 + 人工」结合。
4. **时标图布局**：如何把网络在时间轴上无重叠、少交叉地画出来，且表达自由时差。

## 3. 数据模型

### 3.1 活动（工作项）

```
Activity {
  id              : string    // 编号，如 A1
  name            : string    // 工作名称
  code            : string    // 清单项目编码（可选）
  unit            : string    // 单位
  quantity        : number    // 工程量
  category        : string    // 工效类别键（如 earthwork）
  predecessors    : string[]  // 紧前工作 id（人工可改）
  manualDuration  : number|null // 人工指定工期（天），null=自动

  // —— 工期估算结果 ——
  estDuration     : number    // 自动建议工期
  durationSource  : enum      // auto | auto-fixed | auto-fallback | manual

  // —— CPM 结果 ——
  es, ef, ls, lf  : number    // 最早/最迟开始与完成

  // —— 布局结果 ——

}
```

```
Project {
  projectName         : string

  milestones          : [{ name, date }]

```

## 4. 核心模块设计

### 4.1 PDF 解析模块

**目标**：从两类 PDF 中提取结构化信息。

| 文档 | 提取内容 |
|------|---------|
| 招标文件 | 项目名称、开工日期、合同工期、关键里程碑（含日期） |
| 工程量清单 | 工作项（编号、名称、单位、工程量、紧前关系），并自动判定工效类别 |

**技术路线**：
1. 用 `pdfjs-dist` 提取**带坐标的文本项**（`str + x + y`），不依赖版面渲染。
2. **行聚类**：按 y 坐标（容差内）把文本项聚成行，按 y 降序得自上而下顺序。
3. **列切分**：行内按 x 排序，用「相邻项 x 间隙 > 阈值」判定列边界（轻量表格识别）。
4. **信息抽取**：招标信息用正则（`开工日期[:：]...`、`合同工期...天` 等）；清单行按列序映射字段。
5. **名称→类别分类**：用有序关键词规则（`config.productivity.js` 的 `categoryKeywords`），命中即返回，用于映射工效类别。

**局限与演进**：真实清单版式千差万别（合并单元格、多级标题、跨页、扫描件），规则法只能覆盖结构化电子 PDF。演进路径：① 可配置的列模板；② 扫描件加 OCR；③ 大模型/ML 表格结构识别；④ 关键字段人工校对界面。**当前原型聚焦结构化电子 PDF 的可用性。**

### 4.2 工期估算模块（半自动）

**自动建议**：`工期 = ceil(工程量 ÷ 工效)`，或对「项/套/系统」等无量纲工作用固定工期。

```
工效基准表（可配置）：
  earthwork: 1200 m³/天
  structure: 400  m²/天
  handover : fixedDays 7
  ...
  fallback : 100 单位/天（无匹配类别兜底）
```

**人工覆盖**：清单中 `manualDuration` 非空即覆盖自动值，并在日志中标注「建议 X 天 → 人工指定 Y 天」，实现**半自动 + 可追溯**。

**演进**：接入定额库（国家/地方定额、企业定额）后，把 `productivity` 替换为定额查询结果即可，接口不变；也可加「班组人数/机械台班」维度做多资源工期估算。

### 4.3 逻辑关系建立模块

优先级：**人工（清单紧前关系） > 模板/规则兜底**。

1. 校验：剔除不存在的紧前 id，输出警告。
2. 若整张清单无任何紧前关系，按 `defaultSequence` 施工顺序模板自动链 FS。
3. （扩展）引入「工艺模板库」表达典型分叉/汇合（如：主体结构完成后，砌筑/屋面/幕墙/机电**并行**，机电与砌筑完成后→精装，各专业完成后→竣工验收），避免纯线性链失真。原型样例数据已体现该分叉逻辑。

### 4.4 关键路径计算模块（CPM，AON）

**正推**（最早时间）：
```
ES(i) = max{ EF(p) | p ∈ 紧前(i) }，起始工作 ES=0
EF(i) = ES(i) + 工期(i)
总工期 = max{ EF(i) }
```

**反推**（最迟时间），按 EF 降序（逆拓扑序）：
```
LF(i) = min{ LS(s) | s ∈ 紧后(i) }，终了工作 LF=总工期
LS(i) = LF(i) - 工期(i)
```

**时差与关键性**：
```
总时差  TF(i) = LS(i) - ES(i)
自由时差 FF(i) = min{ ES(s) | s∈紧后(i) } - EF(i)（终了工作：总工期 - EF）
关键工作：TF = 0
关键线路：由关键工作按时间顺序串联
```

正确性依据：反推按 EF 降序保证处理某工作时其所有紧后已算完（紧后的 EF 必大于该工作的 EF）。

### 4.5 时标布局模块

**X 轴 = 时间**：工作框左边 = `ES × pxPerDay`，框宽 = `工期 × pxPerDay`。
**Y 轴 = 分层**：用**区间图贪心着色**避免时间重叠的工作同层——
按 ES 升序，把每个工作放进第一个「当前空闲」的层（该层最后工作的 EF ≤ 本工作 ES）。区间图着色在按起点排序时贪心即最优，可保证用最少层数。

输出每个工作的画布坐标与总图幅。

### 4.6 图形渲染模块

图元约定（遵循时标网络图规范）：
- **工作框**：实心矩形，长度=工期，位置=最早时间；关键工作红框、非关键蓝框。
- **逻辑箭线**：紧前→紧后，关键线路红色粗线。
- **自由时差**：框右侧**橙色波浪线**，长度=自由时差（时标网络图的标志性表达）。
- **里程碑**：菱形节点（开始/结束）+ 招标里程碑三角标记。
- **时间轴**：顶部按周（7 天）刻度，标注日期与天数。
- **图例**：关键工作 / 非关键工作 / 自由时差 / 关键线路。

渲染顺序：网格 → 时间轴 → 波浪线 → 工作框 → 箭线 → 框内文字 → 里程碑 → 图例。

**PNG 转换**：`@resvg/resvg-js` 将 SVG 栅格化（2x 高清），加载系统中文字体保证中文正常显示。

## 5. 关键算法伪代码

### 5.1 CPM

```
function runCPM(activities):
    byId = index by id
    succ = { id -> [后继 ids] }

    # 正推
    for a in activities:
        a.es = a.predecessors ? max(ef of preds) : 0
        a.ef = a.es + a.duration
    T = max(ef)

    # 反推（EF 降序）
    for a in sort(activities, by ef desc):
        S = succ[a.id]
        a.lf = S ? min(ls of S) : T
        a.ls = a.lf - a.duration

    # 时差
    for a in activities:
        a.tf = a.ls - a.es
        a.ff = S ? min(es of S) - a.ef : T - a.ef
        a.critical = |tf| < ε
```

### 5.2 时标分层（区间图着色）

```
function layout(activities):
    sorted = sort by (es asc, duration desc)
    laneEnds = []
    for a in sorted:
        lane = 0
        while lane < len(laneEnds) and laneEnds[lane] > a.es: lane++
        if lane == len(laneEnds): laneEnds.append(0)
        laneEnds[lane] = a.ef
        a.lane = lane
        a.x = x0 + a.es * pxPerDay
        a.width = a.duration * pxPerDay
        a.y = y0 + lane * laneHeight
```

## 6. 接口设计（原型 CLI / 函数级）

### 6.1 命令行

```bash
node src/index.js                              # 内置样例
node src/index.js --bid a.json --boq b.json    # 自定义 JSON
node src/index.js --bid-pdf a.pdf --boq-pdf b.pdf  # 自定义 PDF
node src/index.js --out ./dir                  # 输出目录
```

### 6.2 核心函数签名（可直接封装为服务）

```js
estimateDurations(activities) → log[]      // 半自动工期
buildLogic(activities)          → log[]    // 逻辑关系
runCPM(activities)              → { projectDuration, criticalPath }
layout(activities, opts)        → 布局结果
renderSVG(project, activities, layout, opts) → svg 字符串
svgToPng(svg, outPath, {scale}) → bytes
parseBidPdf(path) / parseBoqPdf(path) → 结构化对象
```

**服务化演进**：上述纯函数可封装为 REST/消息服务（`POST /schedule/generate`，入参为 JSON 或上传文件，出参为图片 URL + 结果 JSON），前端做「建议工期编辑 + 逻辑关系拖拽调整」后重新计算。

## 7. 技术栈选型

| 层 | 原型（本仓库） | 生产建议 |
|----|--------------|---------|
| 语言/运行时 | Node.js ≥18（纯 JS） | 与原型一致，或 Python（`pymupdf`/`pdfplumber` + `matplotlib`/`pyecharts`） |
| PDF 解析 | `pdfjs-dist` | `pdfplumber`/`camelot`（表格更强）、OCR（扫描件） |
| PDF 生成（样例） | `pdf-lib` + `@pdf-lib/fontkit` | 不用于生产 |
| 图渲染 | 手写 SVG + `@resvg/resvg-js` | `matplotlib` / `echarts` / 前端 `antv-x6`（可交互） |
| 网络算法 | 自研 CPM | `networkx`（Python）或自研 |

选型理由：原型用 **Node.js 零运行依赖 + 手写 SVG**，保证「开箱即跑、跨平台、输出可控（矢量+位图）」，避免重依赖安装成本。生产若需更强表格解析与交互，建议 Python 或 Web 前端技术栈。

| 局限 | 扩展方案 |

## 9. 原型运行验证结果

以「某办公楼建设项目」样例（13 项工作，含 1 项人工工期覆盖）验证：

- **工期估算**：自动估算 12 项，人工覆盖 1 项（幕墙建议 15 天 → 人工 20 天）。
- **关键线路**：`A1 → A2 → A3 → A4 → A5 → A6 → A7 → A11 → A13`，总工期 **92 天**。
- **时差**：屋面/室外工程 TF=21 天、幕墙 TF=9 天、机电 TF=1 天（均以波浪线表达自由时差）。
- **输出**：SVG 矢量图 + 2x 高清 PNG + 机读 JSON。
- **PDF 端到端**：`招标文件.pdf` + `工程量清单.pdf` → 解析 → 出图，链路可用。
